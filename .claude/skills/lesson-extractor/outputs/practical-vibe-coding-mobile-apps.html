Where this sits

This video is about building a phone app with the help of AI coding assistants. Mobile app development is writing the software that runs on phones. React Native is a popular framework that lets you write one codebase (in JavaScript / TypeScript) that runs on both iPhone and Android, and Expo is a toolkit that makes React Native much easier to start, run, and ship. AI coding assistants (Claude Code, Cursor, GitHub Copilot, OpenAI Codex) are tools where you describe what you want in plain English and the AI writes and edits the code in your project for you.

The term in the title, vibe coding, was coined in early 2025 to mean leaning fully on AI and barely reading the code. It is fast but tends to collapse on anything serious. This tutorial pitches a disciplined middle path it calls practical vibe coding: keep AI's speed, but add just enough structure (a project rules file, scoped prompts, constant verification) that the AI always knows what it is working on and you never lose the thread. The app being built (a Duolingo clone with lessons and a talking AI language teacher) is just a realistic vehicle for showing the workflow on something bigger than a toy.

What you need coming in

The first half needs almost nothing. Steps 0 to 14 (roughly the first dozen features) run in the free Expo Go app on any phone, with no native build, so your operating system does not matter until you add Stream's audio later.

Genuinely essential

  • Basic comfort with a code editor and terminal (you run commands and edit files, even if AI writes most of the code).
  • Node.js and npm installed (so npx works).
  • An AI coding assistant. The video uses Claude Code on Sonnet (~$20/mo) but says any agent works.
  • A phone with the free Expo Go app for the early build.
  • Free accounts: Clerk, Stream, PostHog, plus GitHub and CodeRabbit.

Helpful, not required

  • Prior React / React Native knowledge (the creator suggests his "React Native full course 2026" first to learn the framework by hand).
  • A feel for auth, state, and APIs (it helps you write better constraints; the AI fills gaps).
  • Later half only: a native build environment. macOS + Xcode for iOS, or Windows / Linux + Android Studio. Needed only once you add Stream audio.
  • No Python needed, despite the app including a Python service. The point is that AI writes it.

Start here · the terms

AGENTS.md
A markdown file at the project root that tells AI agents how the project works: role, stack, folder structure, styling rules, patterns. The first file the agent reads. The backbone of this whole method.
Agent / coding agent
An AI assistant that can read and edit your codebase (Claude Code, Cursor, Copilot, OpenAI Codex, Windsurf).
Agent skills
An open standard: a reusable instruction pack teaching your AI to use a specific tool correctly and on its current version. Installed with npx skills add.
MCP
Model Context Protocol. Lets AI tools query a service directly (for example asking PostHog "which screen has the highest drop-off?") and act on the answer.
Context7
A service that fetches the latest docs for a library so the AI does not rely on outdated training data.
React Native
Framework for building iOS and Android apps from one JavaScript / TypeScript codebase.
Expo
A toolkit on top of React Native that simplifies setup, running, and shipping.
Expo Go
A free phone app to preview your project instantly by scanning a QR code. No full build. Works only until you add native modules.
Development build
A custom build compiled with native code included (needed once you use native modules like Stream audio). Same Expo experience, built through Xcode or Android Studio.
Expo Router
File-based navigation for Expo. Folders and files become screens and routes.
Route group
A folder in parentheses like (auth) that organizes screens without adding to the URL. Purely structural.
Metro bundler
The tool that compiles and serves your React Native code during development.
pre-build
An Expo command turning your config into a full native ios/android folder. --clean wipes old generated code first.
NativeWind
A library to write Tailwind CSS utility classes (like flex-1) to style React Native apps. The video uses v5.
Tailwind CSS
A styling system based on small utility classes instead of separate stylesheets.
Zustand
A small state-management library: shared app state without prop-drilling or Redux boilerplate. (Transcript garbles it as "Zastand / Zustin".)
AsyncStorage
Local key-value storage on the device for small, non-sensitive data. Used here instead of a database for the MVP.
Clerk
A managed authentication and user-management service: email/password, social login, OTP, sessions, billing.
OAuth / SSO
"Sign in with Google / Apple / Facebook." Single sign-on through an external provider rather than a new password.
OTP
One-time passcode: the short numeric code emailed for verification or passwordless sign-in.
JWT / JWKS
A signed token proving who a user is (JWT), verified against the provider's public keys (JWKS). Central to the security fix.
Token provider
A small server endpoint that mints a secure token for a service (here Stream) so the secret key never ships in the app.
Expo API routes
Server-side endpoints inside an Expo app (similar to Next.js). Used to keep secrets off the client.
Stream
A service handling real-time audio/video infrastructure: sessions, participant state, low-latency transport, lifecycle.
Vision Agents
Stream's open-source Python framework for real-time voice/video AI agents. Here it runs as a separate service that joins the call as the AI teacher.
WebRTC
The device technology for real-time audio and video. The audio transport under the hood.
VAD
Voice Activity Detection: deciding when someone is speaking. "Server VAD" (energy-based) fires fast; "semantic VAD" waits to understand intent and is slower.
OpenAI Realtime
OpenAI's low-latency speech model. The brain of the AI teacher's spoken conversation.
PostHog
A product-analytics platform: events, funnels, retention, session replays, feature flags, with an AI wizard that auto-instruments your project.
CodeRabbit
An AI code-review tool that reviews each pull request (and works in the editor), flagging bugs, security issues, and style drift.
Homebrew / CocoaPods
macOS tooling: Homebrew is a package manager; CocoaPods links native iOS libraries into an Xcode project (pod install).
XP
"Experience points." The gamification reward shown per lesson, Duolingo-style.

The core, part 1 · the method

IAvoid both extremes

Pure vibe coding (give in to AI, never read the code) flies for three features then collapses: you ask for one fix, something else breaks, and you are staring at code you cannot explain. Over-engineering is the opposite trap: days of folder structures, tokens, and architecture docs before a single screen exists, which feels productive but ships nothing.

Why it mattersThe fix is a disciplined middle: AI speed plus just enough structure, building one feature at a time and verifying each before the next.

IIPut project context in one file: AGENTS.md

Create AGENTS.md at the project root. It is written for the AI, not for you, and is the first file tools like Cursor and Claude Code read. Without it you re-type the same context every prompt, and the moment you forget a line the AI invents its own choice (a different state library, folder convention, or styling approach), so across 20 prompts the codebase looks like five people built it.

It contains: a role ("you are an expert React Native + Expo engineer, prioritize clarity over abstraction"), a one-paragraph overview, the stack (one line per library so AI stops suggesting alternatives mid-build), the folder structure, styling rules and quirks, and the patterns to follow. Do not write it perfectly up front; add a rule when a problem keeps recurring.

Why it matters"Solve it once, document it, move on." A recurring NativeWind + SafeAreaView issue became one rule, and the AI never repeated the mistake.

IIIEvery prompt has the same four parts, in order

1. Point to AGENTS.md
"Read AGENTS.md first and follow it strictly," every time, because agents do not remember previous sessions.
2. One task
Exactly one feature, screen, or integration. Not "set up NativeWind and build onboarding and add auth," which is three prompts hiding as one.
3. Constraints
Protect what works: "do not change the screen design," "keep the existing Stream audio flow intact," "don't expose secrets."
4. Design references
Attach an image when the task is visual. AI reads a layout better than a description of one.
"A perfect prompt is just an instruction with a defined scope."

IVConstraints are about behavior, not code

The common mistake is writing a constraint that does not constrain anything, because people think about code when they should think about behavior. Do not tell the AI how to write the code; tell it how the feature should behave: what already works and must stay, what may change, what is off limits. Examples: "if anything is unclear, ask before implementing"; "do not expose any secrets"; "keep the existing Stream audio flow intact."

Why it mattersFind constraints by looking at the app like a product engineer: what could go wrong for a user, what might the AI accidentally refactor that already works.

VFor non-visual features, describe behavior and add a test utility

State management, auth logic, and backend integrations have nothing to attach. Describe the behavior instead ("store the selected language in Zustand with AsyncStorage; if an authenticated user has no language, route them to selection, then home; preserve the existing UI"). Also prompt for the infrastructure that lets you verify it, like a temporary "clear storage" button you remove later.

Why it mattersPrompt for the thing that lets you test the feature, not just the feature itself.

VIKeep the AI on the current version of your tools

AI training data lags by months, so it writes code using deprecated methods or old APIs that break at build time. Three fixes: paste the current docs into the prompt under a divider; install agent skills once so the AI always uses the right version (Expo, Clerk, Stream all publish them); or use Context7 / MCP to pull the latest docs on demand.

Why it mattersWhen unsure whether the AI knows a library's current version, assume it does not, and feed it the real docs.

VIIWhen something breaks, write one targeted fix

Breakage is normal, not a failure of the method. Do not re-explain the feature or paste the codebase. State the problem, state the correct behavior, and add a constraint if needed: "the verification modal appears behind the keyboard on iOS; it should sit above it; don't change any other modal behavior or layout."

Why it mattersOne problem, one fix, one verification. Often the simplest move is pasting the raw error message straight into the chat.

VIIIPractice session hygiene

When you finish a feature, close the chat and start a fresh session. Stale context from earlier work leaks in, confuses the agent, and spends more tokens. Stay in the same chat only when the next step is directly tied to what you just built (for example fixing an error from the same change).

Why it mattersFresh session per feature; same session only for tightly-coupled follow-ups.

IXThe tooling is your call; spend tokens wisely

The workflow is agent-agnostic (Copilot, Claude Code, Codex, Cursor, Windsurf all work the same once you are inside). The video uses Claude Code on Sonnet with thinking on (Claude Pro ~$20/mo), optionally topped up with OpenAI Codex Go (~$8/mo). Tip shown: you can speak prompts with the mic button instead of typing.

Why it mattersPick the tool you already pay for; the thinking and the specs are what matter.

XReview everything, and build on hard-coded data first

Run a code review on every change (the video uses CodeRabbit on each PR and in the editor); reviewing AI-generated code matters more than reviewing hand-written code. Separately, build the full UI and MVP on typed hard-coded data before adding any database, so you can iterate fast and reach market, then swap in a backend once the structure is proven.

Why it matters"That's how good developers build: MVP the features with hard-coded data first, integrate the database after."

XIEventually, stop following and start experimenting

Near the end the creator deliberately hands one feature (live captions) to the viewer to attempt first. Once you understand the moving pieces, the real skill is guiding the AI yourself using the context it already has, not memorizing prompts.

Why it matters"Knowing when to stop following tutorials step by step and start experimenting" is called the most underrated skill in AI-assisted building.

The native-build half (step 15 onward) is taught entirely on macOS + Xcode for iOS. The video tells Windows and Linux viewers to "pause and find a guide" for Android Studio. Here is that missing mapping, so you can follow along on Windows or Linux targeting Android.

Context & corrections

This is a hands-on technical tutorial, so most of it is just demonstrated and self-verifying. The checkable claims are mostly the sponsor pitches; they hold up as of mid-2026, with one timing nuance.

Supported"Andrej Karpathy, an OpenAI founding member, posted about vibe coding."

Correct. Karpathy (an OpenAI co-founder) coined "vibe coding" in a February 2025 post; it was even Collins Dictionary's 2025 Word of the Year. (The transcript's "Andre Carpathy" is just a spelling slip.)

Supported"Clerk's free plan gives up to 50,000 monthly retained users."

Accurate for when this video is set: Clerk raised its free tier from 10,000 to 50,000 monthly active users in February 2026. Nuance: if you follow along from older materials, the number was 10,000, so check Clerk's current pricing page rather than trusting any video.

Supported"Stream's Vision Agents is open-source."

True. It is an open-source Python framework for real-time voice/video AI agents (GitHub: GetStream/Vision-Agents), with day-one support for models like OpenAI Realtime and Gemini Live. You still pay for the OpenAI key and Stream's network, but the agent framework itself is genuinely open.

Supported, with context"Nvidia's CEO said they use CodeRabbit all over Nvidia."

Jensen Huang is on record saying "We're using CodeRabbit all over NVIDIA," so the quote is real. The implied argument ("good for a huge company, so good for your project") is a marketing appeal-to-authority, not evidence it fits your use case. Useful tool, but judge it on your own results.

Opinion"This is the only way to build mobile apps with AI without spaghetti code."

Presented as fact, but it is a stylized pitch. The underlying principles (project context file, scoped prompts, verify-as-you-go, review everything) are widely endorsed, yet they are not the single "only" path, and they sit inside a sponsored stack. Take the workflow; stay skeptical of "only."

Opinion"You don't need to learn Python; it's not the lines of code that matter."

A reasonable stance for shipping an MVP, and broadly true that AI lowers the syntax barrier. But it is a judgment call, not settled fact: for debugging, security, and long-term maintenance, understanding the code you ship still matters, which is partly why the video leans so hard on automated review.
